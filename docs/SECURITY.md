# Security boundaries

FXL is parsed by a sticky token scanner and recursive statement parser. It does not execute expressions, import files, evaluate JavaScript or interpret provider text as a command. Model and patch validation runs locally. Files, source bytes, geometry counts and nesting have explicit limits. Generated FXL is never written until valid.

Providers are opt-in and have fixed executable names and argument arrays. `spawn` uses `shell:false` and hidden Windows windows. Prompt text is stdin, never a command line. Native `.exe`/Unix executables are supported; shell wrappers are not silently invoked. Subprocesses receive a newly created temporary working directory rather than the user's project. Only that directory is removed after generation.

Codex: explicit read-only sandbox, shell/unified-exec disabled, user config and exec rules ignored, hooks/plugins/apps/multi-agent disabled, web search disabled, ephemeral execution. Authentication still uses the existing CLI account. Claude Code: bare mode, no built-in tools, MCP denied and empty strict MCP configuration, dontAsk permission mode, no user/project settings or persistent session. Old/incompatible CLIs fail; Formixel never retries with relaxed permissions.

These settings are application restrictions, not a universal operating-system isolation guarantee. Both CLIs are trusted installed programs and retain their own account/authentication behavior. A compromised executable, managed organization hooks/policies, require independent OS sandboxing. Timeout/output-budget cancellation targets the owned process tree (Windows PID-scoped taskkill, Unix process group) and waits for the child close event before temporary-directory cleanup. If Windows denies taskkill, the direct child is forcibly stopped; descendant cleanup then requires an OS environment that permits owned-tree termination. A release test checks an actual spawned descendant. Do not add arbitrary executable paths or arbitrary extra flags to user tasks. Keep PATH trusted.

API providers use fixed HTTPS origins and environment keys. No configurable endpoint, automatic provider fallback, retry or key logging. Requests contain the prompt and compact grammar; no local project files are sent. Timeout and response-size limits apply; incomplete/truncated provider envelopes fail. Error messages include HTTP status, not raw API bodies or stderr that might contain credentials. The CLI does not set up account auth or install providers.

Outputs use same-directory exclusive temporary files. Default output installation uses a hard link that fails atomically if the destination exists, including a concurrent writer appearing after preflight. Explicit `--force` uses rename to replace a requested target only after successful compilation. Output filesystems must support hard links (NTFS and ordinary Linux filesystems do); Formixel does not silently downgrade to a non-atomic write. Input and output paths are explicitly supplied by the local user. These are single-user CLI guarantees, not protection against a hostile process controlling ancestor directories. No background watcher or network server is started.

MCP accepts FXL strings only. No file paths, shell commands or model provider calls. Only newline-delimited JSON-RPC is accepted on stdin; logs stay on stderr. Oversized frames fail closed. The plugin exposes an editor dialog and task export, with no eval, fetch, shell or localhost listener. It validates source before creating a project.

Report vulnerabilities privately through the repository owner's GitHub contact. Never commit `.env`, account data, provider transcripts or API keys. Before release, re-audit dependencies and adapter flags against supported CLI versions.

Resource caps: CLI documents 16 MB; FXL/provider source 2 MB; prompts 32 KB; 10,000 cubes/1,000 groups/depth 32; 262144 pixels; 10,000 keyframes; renderer 1024 dimensions/100 million candidate pixels. Static PNG parsing verifies CRC and bounded inflated output. No external textures are opened. Doctor reports installation/auth booleans and model-free version text; keys/auth bodies are never emitted.
